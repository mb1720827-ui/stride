# Stride Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A web app where you type a task, habit or skill in plain words, your laptop's Claude Code drafts a plan, and the app schedules it into your free time and reminds you with web push.

**Architecture:** Next.js app on Vercel plus a Supabase project shared with Takeaway (tables prefixed `stride_`). Deterministic TypeScript modules do the scheduling and adapting. A laptop worker (Claude Code headless, signed in as the owner) does all AI drafting. Supabase `pg_cron` calls `/api/tick` every 5 minutes to send due push notifications through a `SECURITY DEFINER` function.

**Tech Stack:** Next.js 16.4.6 (App Router, Server Actions, Cache Components), React 19.3, TypeScript, Tailwind 4.3, Supabase (`@supabase/ssr`, `@supabase/supabase-js`), Zod 4, Vitest 5, `web-push`, `tsx`, Claude Code CLI.

**Spec:** `docs/superpowers/specs/2026-11-24-stride-design.md`

## Global Constraints

- Supabase project `malmwezuievheqenqrxv` (shared with Kudi AI, ExamPal, Takeaway). Never touch project `dilhsyykvfxdieswqolm` (Funnecta).
- Every table: `user_id uuid not null default auth.uid()`, row-level security, policy "Owners manage their rows". No service-role key anywhere; tokens stored only as SHA-256 hashes; no secrets in `NEXT_PUBLIC_` variables.
- Defaults: time zone `Africa/Lagos`; quiet hours 22:30–06:30; at most 8 notifications a day (morning brief and evening check-in always fit); wake 06:00; sleep 22:30; evening check-in 21:00.
- Free-time defaults: Mon–Fri 18:00–22:00; Sat–Sun 10:00–13:00 and 16:00–20:00.
- Habits: 3–5 levels; weekly check: 6–7 of 7 done → offer level up; 4–5 → stay; ≤3 → level down with a reason. Two misses in a row → next session uses the minimum version.
- Tasks: leave the last 20% of the time before the deadline free when possible; unplaceable steps mark the task "at risk".
- Reminders: after 14 check-ins a habit's time moves to the median check-in time within its window; 5 ignored reminders in a row (no action within 2 hours) → that plan's reminders fold into the morning brief.
- Skills: 5-question milestone quizzes; 4–5 right passes.
- The AI only drafts; nothing reaches the schedule until the user accepts. All AI output is validated with Zod (`z.toJSONSchema(schema, { target: "draft-7" })` for Claude Code).
- The worker signs in as the owner (`STRIDE_EMAIL`/`STRIDE_PASSWORD`), so it can only see the owner's rows.
- Copy Takeaway's conventions: `src/lib/supabase/server.ts`, `src/proxy.ts`, `requireUser()`, `FormState`, pages wrapped in `<Suspense>`, `await connection()` before reading the clock.

## Review Focus

1. **Time zones around midnight and DST.** An item at 23:30 Lagos time is stored on the right UTC instant and shows on the right local day; a DST zone (America/New_York, 2026-03-08) doesn't shift items by an hour. Tests in Task 3.
2. **Deadline too close or already passed** ("submit in 1 hour", yesterday). No crash: steps that don't fit are returned as unplaced and the task shows "at risk". Tests in Task 4.
3. **No free time configured** (every day empty). The scheduler places nothing and the UI says to add free time in Settings. Tests in Task 4.
4. **Laptop off.** A request stays queued, Today says "Waiting for your laptop" after 2 minutes, and quick-add forms still work. Covered in Task 10's E2E check.
5. **Two tabs or the worker generating the same day's habit items at once.** No duplicates, because of the unique index on `(plan_id, starts_at)` and `upsert … ignoreDuplicates`. Tested in Task 7.

### Task 4: Scheduler

**Files:** Create `src/lib/schedule.ts`, `src/lib/schedule.test.ts`

**Interfaces — Consumes:** Task 3. **Produces:**
- `type Block = { start: string; end: string }`; `type FreeBlocks = Record<string, Block[]>`; `type Slot = { start: Date; end: Date }`
- `DEFAULT_FREE_BLOCKS: FreeBlocks`
- `freeSlots(blocks: FreeBlocks, tz: string, from: Date, to: Date, busy: Slot[]): Slot[]` (free blocks of each local day in range, clipped to `[from, to]`, minus `busy`, sorted)
- `placeSteps(steps: { title: string; minutes: number }[], slots: Slot[], deadline: Date): { placed: { step: number; title: string; starts_at: Date; minutes: number }[]; unplaced: number[] }`: in order, each step in the earliest slot with room, never past the deadline; first tries with only slots ending before `now + 80%` of the time left, then falls back to the full range for steps that didn't fit.
- `placeDaily(days: string[], minutes: number, tz: string, blocks: FreeBlocks, preferred: number /* minutes from midnight */, busy: Slot[]): Date[]`: one start per day at `preferred` if free, else the nearest free start in that day's blocks, else `preferred` anyway (habits can sit outside free blocks, e.g. waking up).
- `placeWeekly(weekStart: string, sessions: number, minutes: number, tz: string, blocks: FreeBlocks, busy: Slot[]): Date[]`: spreads sessions over different days (Mon→Sun, every other day first), earliest fitting slot each day.
